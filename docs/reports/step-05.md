## 실행 조건

- `src/test_audio.py`, bfloat16, 텍스트+오디오(570M)
- 로드 후 RSS 2132 MB, 최종 RSS 3235 MB
- 지연: 1회 3560 ms, **2회 367 ms** (WAV 3개)
- tegrastats(0.5 s): 보드 RAM 3275 → 최대 5811 / 7486 MB, GR3D_FREQ 최대 57%
- 같은 보드: 팀원이 카메라 녹화(`cam.py`) 중, 팀원 시계열 서비스·수집기. 다른 계정 모델 로드 없음.

## 관찰

- 같은 오디오 임베딩에 질의만 바꿔 본 결과 (speech / beep / noise, 768차원):

  | 질의 | 점수 | 1위 |
  |---|---|---|
  | 덥다고 냉방을 요청하는 목소리 (원문) | 0.648 / 0.622 / 0.648 | noise (동점권) |
  | 사람의 말소리 | 0.649 / **0.667** / 0.644 | beep (오답) |
  | 한국어로 말하는 여자 목소리 | 0.601 / 0.589 / 0.574 | speech |
  | 에어컨을 켜 달라는 말 | **0.685** / 0.596 / 0.648 | speech (차이 0.037) |
  | a person speaking Korean | 0.666 / 0.619 / 0.649 | speech |
  | 원문 질의, 프롬프트 없음 | 0.693 / 0.728 / **0.741** | noise (오답) |

  → 말의 **내용**("에어컨을 켜 달라")으로 물으면 잘 찾고, "목소리/말소리"라는 **소리의 종류**로 물으면 약하다.
- 오디오끼리 코사인: speech-noise 0.764, beep-noise 0.770, speech-beep 0.677. 자기 자신과 0.996~0.999 (bfloat16 정밀도, 3단계 dtype 관찰과 같은 현상).
- 첫 encode 3560 ms vs 두 번째 367 ms. 오디오 전처리·커널 첫 로드 비용이 크다.
