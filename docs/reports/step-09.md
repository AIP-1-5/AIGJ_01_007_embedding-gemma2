## 오프라인 검증 (`src/test_pose_logic.py`, 23/23 통과)

YOLO를 가짜 모듈로 바꾸고 합성 관절 좌표(정면, 어깨 너비 100px)를 `update_person`에 넣었다. CPU만 사용, 모델·카메라 없음.

| 확인 | 입력 | 결과 |
|---|---|---|
| 한 프레임 규칙 | 기본 / 두 손목 위 / 한 손목 위 | 기본 / 만세 / 한팔들기 |
| 정면 점수 | 정면 / 코를 귀 사이에서 30% 이동 | 1.000 / 0.400 (`FACE_TH` 0.6 미만) |
| 9-1 깜빡임 재현 | 한팔들기 3초, 3프레임마다 1프레임 손목이 어깨선으로 떨어짐 (15 fps) | raw **한팔들기 15회**, smooth **1회** |
| 9-2 손 흔들기 | 올린 손목 x를 1.5 Hz로 ±0.4 어깨너비 | smooth: 손흔들기 1회 / raw: 한팔들기만 |
| 9-5 행동 패턴 | 이동+옆 / 이동+정면 2초 / 정지+정면 6초 / 정지+옆 12초 | 지나감 / 힐끗 봄 / 관심 있음 / 머무름 |
| 악수 | 두 손목 10px, 가슴 높이 / 멀리 떨어짐 | 후보 / 후보 아님 |
| 9-3 → 9-6 형식 | `--record` CSV를 `train_pose.load_sequences`로 읽기 | 505행 전부 56열, 특징 53차원 (= `N_FEAT`) |
| 9-6 불러오기 | 무작위 가중치 체크포인트(학습 아님) → `load_model`/`predict` (CPU) | 동작 |

이 검증은 **규칙이 원문 설명대로 동작하는지**만 본다. 실제 관절 잡음, 측면 자세, 거리에 따른 신뢰도 저하는 카메라로만 확인할 수 있다.

## 실행 순서 (카메라를 쓸 수 있을 때)

1. 실행 전 Claude가 `free -h`·다른 계정 프로세스를 확인하고 묻는다(팀 규칙). yolo11n-pose는 `/srv/team5/models`에 있어야 한다.
2. 9-1 `--raw` → 9-2 기본 → 9-5 `--behavior` 순서로, 맥 브라우저 `http://<보드 Tailscale IP>:8002`를 보며 동작한다. 횟수는 `runs/pose/<모드>.jsonl` 이벤트로 센다.
3. 9-3 녹화: `data/action/{idle,wave,clap,arms_crossed}.csv`(각 30초 이상), `data/behavior/{passing,glance,interested}.csv`(각 10회 이상). 화면에 그 동작을 하는 사람만.
4. CSV를 맥으로 옮겨 학습([mac-training.md](../mac-training.md) 9-6), `models/*.pt`를 보드로 가져와 `--model`로 추론.

## 관찰 (코드 읽기·오프라인 검증)

- **9-6 행동 모델 라벨과 순위표가 맞지 않는다(원문 그대로).** 원문 파일 이름은 영문(`passing`, `glance`, `interested`)인데 사람별 최종 패턴을 고르는 `BEH_RANK`는 한글 키다. 모델 라벨은 모두 기본값 1로 같은 순위가 되어, 요약의 "최종 패턴"이 처음 나온 라벨에 고정될 수 있다. 화면 영문 표시(`EN`)도 라벨을 그대로 보여 준다. 판정 로직을 원문과 같게 두기 위해 고치지 않았다. 녹화 파일을 `지나감.csv`, `힐끗 봄.csv`, `관심 있음.csv`처럼 한글 이름으로 하면 코드를 바꾸지 않고 맞출 수 있다(선택, 9-3 전에 정한다).
- 합성 데이터에서 raw 15회 대 smooth 1회는 "3프레임마다 1프레임 잡음"을 가정한 값이다. 실제 깜빡임 정도는 카메라로 재야 한다.
- `--behavior`를 켜면 정면에서 가만히 한팔들기만 해도 3초 뒤 "관심 있음" 이벤트가 같이 생긴다. 9-4 횟수를 셀 때는 동작 이벤트만 센다.
