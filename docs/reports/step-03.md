## 관찰

- 전체 유사도 (768, 프롬프트 on, bfloat16). 행=질의, 열=CO2/에어컨/조도/Jetson:
  ```
  [[0.717 0.616 0.71  0.585]
   [0.649 0.725 0.655 0.594]]
  ```
  질의 1의 1위(CO2 0.717)와 2위(조도 0.710) 차이가 **0.006** (128차원은 0.003). 통과지만 아슬아슬하다.
- 프롬프트 off: 질의 1 → 조도 문장(768 0.747, 차이 0.040). 질의 2는 맞지만 점수 분포가 전반적으로 올라감(0.823).
  프롬프트 문자열: 질의 `task: search result | query: `, 문서 `title: none | text: `.
- 차원을 줄이면 점수 절댓값은 올라가고(0.717 → 0.785) 1-2위 차이는 줄었다(0.006 → 0.003).
- 첫 실행 지연(161 ms)과 이후(150 ms)의 차이가 작다. 짧은 질의 2개는 GPU 사용률이 최대 15%로, 지연 대부분이 GPU 계산이 아닌 토큰화·파이썬·커널 실행 오버헤드로 보인다(추정).
- dtype 실험 (scratchpad, 텍스트 50/943/2823 토큰):
  - NaN: bfloat16·float16·float32 모두 없음. **float16 NaN은 이 조건에서 재현되지 않았다.**
  - float32 대비 코사인: bfloat16 `1.0025, 1.0037, 1.0003` / float16 `0.9999, 1.0, 1.0003`.
  - 최대 할당: bf16·fp16 860 MB, fp32 1446 MB.
  - 짧은 4문장 유사도는 bf16과 fp16이 소수 셋째 자리까지 거의 같음.
- 길이 실험: 약 14,100토큰(60회 반복 2,823토큰에서 환산, 추정) 문서 → `torch.OutOfMemoryError: Tried to allocate 1.48 GiB` (sliding window attention mask). 8192로 자른 뒤 같은 문서 `(1, 768)`, 최대 할당 1749 MB.
