# 단계별 결과

단계마다 `step-NN.md`를 만든다. 형식:

```markdown
# N단계 <이름>

날짜 · 보드 · 실행한 사람(계정만)

## 완료 조건 판정
| 조건 (원문 확인 포인트) | 측정값 | 통과 여부 | 미통과 원인 |

## 실행 조건
torch / sentence-transformers 버전, dtype, 전원 모드, 같은 보드에서 동시에 돈 프로세스

## 관찰
숫자와 출력 요약 (사진·영상 파일은 넣지 않는다)
```

## 6단계 성능 측정표

지연은 두 번째 실행 값. 측정 중 다른 계정 프로세스가 있었으면 비고에 적는다.

| 구성 | 로드 크기 | 로드 후 RAM (MB) | 입력 | 지연 (ms) | GPU 사용률 (%) | 비고 |
|---|---|---|---|---|---|---|
| 텍스트 전용 | 270M | 1680 | 질의 2개 | 146 | 12 | GPU 할당 최대 530 MB. 1회 571 ms |
| +비전 | 440M | 2020 | 이미지 5장 | 2082 | 99 | GPU 할당 최대 1225 MB. 장당 약 416 ms |
| +비전 | 440M | 2028 | 동영상 10초 | 2007 | 99 | PyAV 1 fps 11프레임 (torchcodec 사용 불가, 4단계). GPU 할당 최대 1248 MB |
| +오디오 | 570M | 2239 | WAV 3개 | 354 | 8 | GPU 할당 최대 1157 MB. 1회 3503 ms |
| 전체 | 740M | 2573 | 혼합 | 4650 | 99 | 질의 2 + 이미지 5 + 동영상 1 + WAV 3. 스왑 749 → 1990 MB |

2026-10-23 보드 A, `src/bench_all.sh`, `~/practice.sh`(MemoryMax 2500M) 안에서 구성마다 새 프로세스. 로드 후 RAM = 프로세스 RSS. 같은 시간 보드에는 공기 측정 프로젝트(수집기 + 8080 추론 서비스, 약 1.5GB)가 함께 돌았다. 자세한 값: [step-06.md](step-06.md).
