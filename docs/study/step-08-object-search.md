# 8단계 웹캠 실시간 물체 추출과 웹 검색

2026-10-23 (노트 작성 10/26) · 결과: [docs/reports/step-08.md](../reports/step-08.md) · 앞 단계: [4단계](step-04-vision.md) (이미지 임베딩), [6단계](step-06-performance.md) (속도·메모리)

> 8-1·8-2는 10/23, 8-3(yoloe)과 "세탁기" 검색은 10/26 결과.

## 한 문장으로
YOLO가 잘라 낸 물체 크롭을 EmbeddingGemma 2로 벡터화해 검색 색인을 만들고, 크롭과 라벨 문구의 유사도로 라벨을 다시 붙여 COCO에 없는 드럼 세탁기를 `microwave`에서 `drum washing machine`(0.722)으로 바로잡았다. 하지만 점수가 0.6~0.75에 몰려 원문 기준값 0.20은 거르는 역할을 못 했다.

## 세미나용 1분 설명
YOLO는 80개 클래스만 아는 검출기라, 처음 보는 물체도 아는 클래스 중 하나로 우겨 넣습니다. 드럼 세탁기 사진을 보여 주니 `microwave`라고 했습니다. 그래서 역할을 나눴습니다. YOLO는 "어디에 물체가 있는지" 박스만 치고, 무엇인지는 임베딩 모델이 판단합니다. 잘라 낸 그림을 벡터로 바꾸고, "a photo of a drum washing machine" 같은 라벨 문장 벡터 중 가장 가까운 것을 고릅니다. 사전에 없는 단어를 만나면 형태소 분석기 대신 의미 검색으로 넘기는 검색 엔진의 폴백과 비슷합니다. 크롭 벡터는 색인에 쌓여서 "세탁기"라고 쳐도 라벨과 상관없이 비슷한 그림을 찾아 줍니다. 대가는 속도입니다. 검출은 초당 14프레임인데 임베딩은 크롭 하나에 0.6초가 걸려서, 두 일을 별도 스레드와 큐로 나눴습니다. 그리고 점수가 전부 0.6 이상이라 "0.2 넘으면 믿는다"는 기준은 이 모델에서 의미가 없었습니다.

## 핵심 개념

### 검출(어디)과 인식(무엇)의 분리
- 정의: 박스 위치는 고정 클래스 검출기가, 라벨은 크롭 임베딩과 라벨 문장의 유사도가 정한다.
- 비유: 택배 분류기에서 컨베이어가 상자를 집어 올리고(검출), 바코드 대신 사람이 내용물을 보고 분류(인식)하는 것. 백엔드라면 라우팅과 처리 로직을 나눈 것.
- 이 레포에서는: `src/app.py:118` — YOLO `track`으로 박스와 추적 ID. `src/app.py:89` — 라벨 문장 벡터를 미리 만들어 둔다. `src/app.py:175` — 최고 유사도가 `LABEL_MIN` 이상이면 라벨 교체.
- 잘못하면: YOLO가 아예 박스를 안 치는 물체(COCO와 너무 다른 것)는 재라벨 기회도 없다. 이것을 푸는 것이 8-3 yoloe.

### 절대 점수 임계값 vs 1·2위 차이
- 정의: "유사도 0.2 이상이면 믿는다"는 절대 기준은 모델마다 점수 분포가 달라서 그대로 옮겨 쓸 수 없다. 1위와 2위의 차(margin)는 분포에 덜 민감하다.
- 비유: 시험 점수 60점 합격선보다 "1등과 2등 차이가 충분한가"를 보는 것. 검색 엔진이 BM25 점수 절대값 대신 순위를 쓰는 것과 같다.
- 이 레포에서는: `src/app.py:72` — `LABEL_MIN = 0.20`(원문 값, 바꾸지 않음). 실제 최고 점수는 모두 0.6 이상이라 모든 크롭이 재라벨됐다. 드럼 0.722 vs 통돌이 0.751처럼 1·2위 차가 0.015인 경우도 있었다.
- 잘못하면: 모르는 물체도 라벨 목록 중 가장 덜 틀린 것으로 바뀐다(모자 → `book` 0.646). [7단계](step-07-finetune.md)처럼 모델을 바꾸면 점수 척도가 바뀌어 기준값이 또 틀어진다.

### 생산자-소비자 큐로 빠른 일과 느린 일 분리
- 정의: 카메라·검출 스레드가 크롭을 큐에 넣고, 임베딩 스레드가 최대 8개씩 꺼내 처리한다.
- 비유: 주문 접수(빠름)와 주방(느림) 사이의 주문서 꽂이. 백엔드의 메시지 큐와 워커.
- 이 레포에서는: `src/app.py:106` `capture_loop` → `crop_q` → `src/app.py:151` `embed_loop`(배치 `min(8, len(crop_q))`). `src/app.py:54` `REFRESH_S = 30`으로 같은 추적 ID는 30초에 한 번만 큐에 넣는다.
- 잘못하면: 큐에 넣는 속도(검출 14 fps)가 빼는 속도(약 1.6개/s)보다 계속 빠르면 큐와 메모리가 늘어난다. 추적 ID와 30초 간격이 사실상 유입을 줄이는 장치다. 화면 밖으로 나갔다 오면 새 ID라 다시 들어간다(10분 103개).

### 공유 자원 잠금
- 정의: 모델 하나를 검색 요청과 임베딩 스레드가 같이 쓰므로 `emb_lock`으로 한 번에 하나만 `encode`한다. 색인 목록은 `idx_lock`.
- 비유: DB 커넥션 하나를 여러 요청이 나눠 쓰는 것. 커넥션 풀 크기 1.
- 이 레포에서는: `src/app.py:92` 잠금 4개, `src/app.py:230` `search`는 색인을 복사(snapshot)한 뒤 잠금을 풀고 계산한다.
- 잘못하면: 잠금 없이 동시에 `encode`하면 GPU 메모리가 순간 두 배가 되거나 결과가 섞일 수 있다. 반대로 검색 중에는 임베딩이 멈추므로 검색이 잦으면 색인 갱신이 밀린다.

## 비교
- 무슨 문제: 고정 80클래스 검출기로는 강의실의 COCO 밖 물체(세탁기, 전지 포장)를 바르게 부르지 못하고, 이름으로 검색할 수도 없다.
- 대안 1 — YOLO만, 라벨 그대로(8-1): 가장 빠르다(13.7 fps). 하지만 세탁기는 `microwave`로 저장돼 "세탁기"로 찾을 방법이 라벨에는 없다. 크롭 벡터 검색은 여전히 가능하다.
- 대안 2 — 오픈 어휘 검출기 YOLOE(8-3): 라벨 문구 자체를 검출 클래스로 쓴다. 실측: fps는 13.5로 yolo(13.7)와 거의 같았지만, 세탁기 사진 격자 화면을 `keyboard`로, 흰 머그를 `mouse`로 검출했다. 라벨 목록에 있어도 "그 문구로 검출된다"는 보장은 없다. 반면 같은 크롭을 임베딩으로 보면 1위가 세탁기였고, "세탁기" 검색도 4개를 모두 찾았다.
- 대안 3 — 크롭마다 VLM(이미지 설명 모델)에 "이게 뭐야" 묻기: 라벨 목록이 필요 없지만 크롭당 수 초, 보드 메모리 2.5 GB 제한 안에 함께 올리기 어렵다.
- 이 방식(relabel)의 약점: 라벨 목록 밖 물체는 가장 덜 틀린 라벨로 바뀐다. 절대 임계값이 무의미해서 "모르겠다"고 말하지 못한다. 크롭당 0.6초라 물체가 많은 장면에서는 색인이 늦게 따라온다.
- 실무 Use Case: 물류 창고 CCTV에서 "파란 팔레트", "깨진 상자" 같은 자유 문장으로 지난 영상을 찾는 기능. 검출기는 박스만 치고, 크롭 벡터를 벡터 DB에 쌓아 문장 검색과 라벨 보정을 같이 한다.

## 실제로 겪은 문제 → 원인 → 해결
- ultralytics 설치가 numpy를 2로 올리려다 pyctcdecode(`numpy<2`)와 충돌 → 원문 Q12 → pyctcdecode 제거 후 설치.
- 첫 실행에서 ultralytics가 `lap`을 torch 고정 없이 자동 설치 → 추적에 lap이 필요하고 AutoUpdate가 켜져 있음 → 앱·pip 중지, `-c torch-pin.txt`로 lap 설치, `YOLO_AUTOINSTALL=False`. torch `2.14.1+cu132` 그대로 확인.
- 프레임마다 `'half' is deprecated` 경고 → ultralytics 8.4 인자 변경 → 동작 영향 없어 그대로 둠(로그만 커짐).
- 8-1 "세탁기" 검색을 하지 않아 미측정 → 실행 중 검색창을 쓰지 않음 → 10/26 yoloe 실행 중 `/search`를 직접 호출해 측정(상위 4개 모두 세탁기, 라벨은 keyboard).
- yoloe가 `clip` 패키지를 요구했는데 교육장 네트워크가 PyPI를 막음(맥도) → GitHub 릴리스·소스에서 torch 고정을 걸고 오프라인 설치.

## 일부러 망가뜨려 볼 실험
1. **라벨 목록에서 정답 빼기** — `LABELS`에서 `drum washing machine`과 `top-load washing machine`을 지우고 같은 크롭을 재라벨. 예상: 세탁기 크롭이 `microwave`나 `refrigerator` 같은 다른 가전으로 바뀌고 점수는 여전히 0.6대. "점수가 높다 ≠ 맞다"를 확인한다. (미실행, 카메라 없이 남은 크롭으로 가능)
2. **`REFRESH_S`를 3으로** — 같은 물체가 3초마다 큐에 들어간다. 예상: 큐 유입이 처리량(약 1.6개/s)을 넘어 `embed_ms`는 비슷한데 색인 반영이 점점 늦어지고 `crops/`가 빠르게 찬다. 카메라가 필요하다. (미실행)
