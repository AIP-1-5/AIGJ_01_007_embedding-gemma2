# 5단계 음성 테스트

2026-10-23 · 결과: [docs/reports/step-05.md](../reports/step-05.md) · 앞 단계: [3단계](step-03-text.md) (코사인 유사도, 검색 프롬프트)

## 한 문장으로
텍스트 질의로 소리 파일 3개를 검색해 경보음·잡음은 맞혔지만, "냉방을 요청하는 목소리"는 0.001 차이로 잡음에 졌다. 말의 내용으로 물으면(“에어컨을 켜 달라는 말”) 0.037 차이로 맞혔다.

## 세미나용 1분 설명
3단계에서 문장과 문장을 같은 지도 위에 놓았다면, 5단계는 소리도 같은 지도 위에 올립니다. 그래서 "날카로운 경보음"이라는 글자로 1 kHz 비프음 파일을 찾을 수 있습니다. 텍스트 검색 서버에 오디오 파일을 색인해 넣었는데 SQL 하나로 같이 검색되는 것과 비슷합니다. 다만 입력 형식 계약이 엄격합니다. 16 kHz 모노가 아니면 결과가 무작위에 가까워집니다. API의 요청 스키마 검증과 같아서, 코드에서 먼저 assert로 막습니다. 재미있던 점은 질문 방식입니다. "사람 말소리"처럼 소리의 종류로 물으면 오히려 비프음이 1위였고, "에어컨을 켜 달라는 말"처럼 말의 내용으로 물으면 정확히 음성 파일을 찾았습니다. 이 모델은 음성을 "무슨 말을 했나" 쪽으로 이해한다는 뜻입니다.

## 핵심 개념

### 멀티모달 공유 벡터 공간
- 정의: 텍스트·이미지·오디오를 각각의 인코더로 바꾸되, 결과 벡터는 같은 768차원 공간에 놓이게 학습돼 서로 비교할 수 있다.
- 비유: 서로 다른 테이블(문서, 이미지, 오디오)을 같은 키 체계로 맞춰 하나의 인덱스로 JOIN 없이 검색하는 것.
- 이 레포에서는: `src/test_audio.py:31` — 텍스트 질의 벡터와 오디오 벡터를 바로 내적한다.
- 잘못하면: 인코더를 다른 모델 버전으로 바꾸면 기존 오디오 벡터와 공간이 달라 점수가 의미 없어진다 → 전체 재색인.

### 입력 형식 계약 (16 kHz 모노)
- 정의: 오디오 인코더는 특정 샘플레이트·채널을 가정하고 학습됐다. 다르면 같은 소리도 다른 패턴으로 보인다.
- 비유: API 요청 스키마. 필드 단위가 ms인데 s로 보내면 에러 없이 틀린 결과가 나온다.
- 이 레포에서는: `src/test_audio.py:19-21` — `sf.info`로 16000/1이 아니면 assert로 중단.
- 잘못하면: 원문 6단계 표의 "오디오 검색 결과가 무작위에 가까움". 예외가 안 나서 더 위험하다.

### 질의 표현과 의미 간격
- 정의: 같은 대상이라도 질의를 어떤 축(소리 종류 vs 말 내용)으로 표현하느냐에 따라 점수가 달라진다.
- 비유: 검색 엔진에서 사용자가 "그 노래 있잖아"로 찾는 것과 가사 한 줄로 찾는 것의 차이.
- 이 레포에서는: `docs/reports/step-05.md` 관찰 표 — "사람의 말소리"는 beep, "에어컨을 켜 달라는 말"은 speech.
- 잘못하면: 사용자 질의를 그대로 쓰면 이번처럼 0.001 차이로 뒤집힌다. 질의 템플릿·예시 질의로 보완한다.

## 비교
- 무슨 문제: 녹음 파일을 "무슨 소리인지"로 검색하기.
- 대안 1 — 음성 인식(STT)으로 글자로 바꾼 뒤 3단계 텍스트 검색: 말 내용 검색은 정확하다.
  - 이 대안을 썼다면: 경보음·잡음처럼 말이 아닌 소리는 글자가 없어 못 찾는다. STT 모델을 하나 더 올려야 해서 8GB 보드 메모리가 빠듯해진다.
- 대안 2 — 소리 분류기(AudioSet 527종 등): "경보음", "빗소리"는 잘 맞힌다.
  - 이 대안을 썼다면: 미리 정한 클래스만 가능하고, "에어컨 켜 달라는 말" 같은 자유 질의는 안 된다.
- 이 방식의 약점: 점수 차가 작다(전체가 0.6~0.7에 몰림). "사람 목소리" 같은 소리 종류 질의에 약했다. 합성음만으로 판정해 실제 목소리 성능은 미측정.
- 실무 Use Case: 공장·서버실 마이크 녹음에서 "금속 마찰음", "경보음"을 텍스트로 검색해 사고 직전 구간을 찾는다. 사람 대화 내용은 STT를 병행한다.

## 실제로 겪은 문제 → 원인 → 해결
- espeak-ng 없음 → apt 설치에 sudo 필요 → gTTS(pip)로 대체.
- gTTS 설치 후 `huggingface-hub 2.2.0 requires click>=8.4.2, but you have click 8.1.8` → gTTS가 click을 내림 → 샘플 생성 후 gTTS 제거, click 8.5.0 복구. 2단계에서 본 것처럼 **제약 파일은 torch만 지킨다**는 실제 사례.
- ffmpeg `sine`·`anoisesrc` 없음 → 보드 ffmpeg가 NVIDIA 최소 빌드 → numpy로 생성.

## 일부러 망가뜨려 볼 실험
1. **질의 표현 바꾸기** — 예상: 비슷한 결과. 실제: "사람의 말소리" → beep(오답), "에어컨을 켜 달라는 말" → speech(차이 0.037), 원문 질의에서 프롬프트를 빼면 noise(0.741)로 오답. 질의가 결과를 크게 바꾼다.
2. **8 kHz로 바꿔 넣기** (해 볼 것) — `librosa.load(..., sr=8000)`로 저장한 파일을 넣으면 `src/test_audio.py:21`의 assert에서 멈춘다. assert를 주석 처리하고 돌려 점수가 어떻게 무너지는지 보면 "형식 계약"의 의미가 보인다. (이번엔 미실행)
