# 학습 노트

공부는 읽기가 아니라 **회상·비교·실패 실험**으로 한다. 노트는 그 재료다.

| 문서 | 언제 | 파일 |
|---|---|---|
| 단계 노트 | 단계 하나가 끝날 때 (`/step-end N`) | `step-NN-<이름>.md` |
| 하루 문서 | 하루 끝 (`/day-end`) | `daily/YYYY-MM-DD.md` |
| 실습 정리 | 실습 전체가 끝날 때 | `summary.md` |

## 깊이

- 임베딩·LLM·컴퓨터 비전은 **개념과 "왜"까지**. 수식과 모델 내부 구조는 깊게 파지 않는다.
- 대신 백엔드 개념(DB 인덱스, 검색, 캐시, 동시성)과 연결해서 이해한다.

## 단계 노트 형식

```markdown
# N단계 <이름>

날짜 · 결과: [docs/reports/step-NN.md](../reports/step-NN.md)

## 한 문장으로
무엇을 했고 결과가 어땠는지.

## 세미나용 1분 설명
동료에게 말로 설명하는 대본. 비유 1개 포함, 6~8문장.

## 핵심 개념 (개념마다 네 줄)
### <개념>
- 정의: 한 줄
- 비유: 일상 비유 한 줄 (백엔드 개념에 대응되면 함께)
- 이 레포에서는: `<파일>:<라인>` — 거기서 하는 일
- 잘못하면: 틀리게 쓰면 실제로 생기는 일

## 비교
무슨 문제를 푸는가 → 대안 1개 이상 → 대안을 썼다면 생기는 문제 → 이 방식의 약점.
실무 Use Case 1개.

## 실제로 겪은 문제 → 원인 → 해결
이 단계에서 실제로 있었던 것만. 없으면 "없음".

## 일부러 망가뜨려 볼 실험 (1~2개)
바꿀 것 → 예상 결과 → 실제 결과(해봤으면).

## 회상 질문 5개
<details><summary>1. 개념: …</summary>답</details>
<details><summary>2. 왜: …</summary>답</details>
<details><summary>3. 트레이드오프: …</summary>답</details>
<details><summary>4. 장애 상황: …</summary>답</details>
<details><summary>5. 내 프로젝트 적용: …</summary>답</details>

> 💡 아이디어: (있을 때만 1~2줄)
```

## 공개 저장소 규칙

- 사람 이름(팀원, 강사)을 쓰지 않는다. "팀원", "강사".
- RTSP 주소, 카메라 IP, 토큰을 쓰지 않는다.
- 사진·영상을 넣지 않는다. 결과는 숫자와 글로.
