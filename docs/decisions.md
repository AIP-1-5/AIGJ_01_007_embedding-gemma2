# 결정 기록

형식: 날짜 · 결정 / 이유 / 버린 대안

## 2026-10-23 · 저장소와 진행 방식

- **결정**: 원문 단계 번호(1~10)를 작업 단위로 쓰고, 단계마다 `/step-start` → 실행 → `/step-end`로 진행한다.
  - 이유: 원문이 이미 순서와 확인 포인트가 정해진 실습이라, 스펙을 새로 쓰는 것보다 원문 단계를 그대로 완료 조건으로 쓰는 편이 빠르다.
  - 버린 대안: 시계열 과제처럼 Spec Kit(spec → plan → tasks). 문서 작성 비용이 실습 시간보다 커진다.

- **결정**: 모델 캐시는 `/srv/team5/hf` 공용 폴더를 쓴다.
  - 이유: 계정이 나뉘어 있어 기본값(`~/.cache`)이면 약 3GB 모델을 계정마다 받는다.
  - 버린 대안: 계정별 캐시. 디스크와 다운로드 시간이 두 배.

## 2026-10-23 · 실행 보드를 보드 A로 변경

- **결정**: 이 실습은 보드 A에서 실행한다. (같은 날 앞서 정한 "보드 B에서만 실행"을 대체한다.)
  - 이유: 보드 A에는 내 시계열 서비스가 없다. 상시로 도는 것은 팀원 계정의 시계열 수집기(약 27MB)뿐이라, 8GB 메모리에서 차지하는 몫이 작다.
    앞선 결정은 "보드 A에 큰 시계열 서비스가 돈다"는 잘못된 전제에서 나왔다.
  - 조건: 팀원 수집기는 멈추거나 건드리지 않는다. 모델을 올리기 전에 `free -h`로 남은 메모리를 확인하고, 4단계 이후(영상·비전, YOLO)는 실행 전에 사용자에게 묻는다.
  - 버린 대안: 보드 B에서만 실행. 전제가 틀렸으므로 보드 A를 피할 이유가 없다.
  - 버린 대안: 메모리 확보를 위해 수집기를 잠시 내리고 실행. 팀원의 상시 수집이 끊기고, 남의 프로세스를 건드리게 된다.

- **결정**: GitHub 접속은 `~/.ssh/config`로 443 포트(`ssh.github.com`)를 쓴다.
  - 이유: 교육장 네트워크가 SSH 22번 포트를 막는다.
  - 버린 대안: HTTPS + 토큰으로 clone/push. 토큰을 보드에 저장해야 하고, 원문 README의 `git@github.com:` 주소를 매번 바꿔야 한다.

## 2026-10-23 · 진행 방식을 연속 진행으로 변경

- **결정**: 1~10단계 구현·실행은 Claude가 승인 대기 없이 연속으로 진행하고, 단계마다 보고서·학습 노트를 쓰고 커밋한다. 사용자는 학습 노트로 회상·비교·실패 실험을 한다.
  - 이유: 사용자의 학습 목표는 구현 자체보다 개념 회상과 비교다. 단계마다 승인을 기다리면 실습 시간(하루 5시간)의 대부분이 대기로 간다.
  - 멈춤 조건: sudo, 물리 작업·비밀값, 4·7·8·9단계 큰 메모리 실행 직전(`free -h` 제시), 10단계 카메라 1대, 같은 오류 2회 반복. 보드 A 팀원 수집기를 건드리지 않는 규칙은 그대로다.
  - 버린 대안: 단계마다 계획 승인 후 실행(기존 방식). 안전하지만 대기 시간이 길다. 위험한 지점만 멈춤 조건으로 남겨 안전을 유지한다.
  - 버린 대안: 커밋을 하루 끝(`/day-end`)에 몰아서. 단계 중간에 실패하면 되돌릴 지점이 없다.

## 2026-10-23 · 학습은 맥에서만

- **결정**: 보드에서는 학습을 돌리지 않는다. 7단계 미세 조정과 9-6 GRU 학습은 맥 GPU(MPS)에서 하고, 보드는 학습된 모델의 추론·평가만 한다.
  - 이유: 보드 A는 8GB를 4개 계정과 팀원의 상시 수집기가 함께 쓴다. 학습은 추론보다 메모리(그래디언트·옵티마이저 상태)를 몇 배 쓰므로, 스왑으로 버티면 보드 전체가 느려지고 수집기까지 영향을 받을 수 있다.
  - 버린 대안: 보드에서 배치를 줄여 학습하고 실패할 때만 맥으로(앞선 지시). 실패 자체가 공용 보드의 메모리 압박을 일으킨다.
  - 버린 대안: Colab 등 클라우드 GPU. 계정·데이터 업로드가 추가로 필요하고, 맥으로 충분하다.

## 2026-10-23 · 팀 진행 규칙 반영

- **결정**: 팀 문서 저장소의 진행 규칙을 이 저장소 규칙(`CLAUDE.md`)에 반영한다. 모델을 올리는 실행은 모두 `~/practice.sh`(보드 자물쇠 + `MemoryMax=2500M`)로 하고, 내 앱 포트는 8002, 보드 A 공기 측정 프로젝트(수집기 + 8080 추론 서비스)는 건드리지 않고 실습 뒤 `/health`를 확인한다.
  - 이유: 보드 A를 팀원 여러 명과 24시간 센서 서비스가 같이 쓴다. 자물쇠가 없으면 두 사람이 동시에 모델을 올려 메모리가 부족해지고 센서 서비스까지 죽을 수 있다.
  - 확인: 5단계 오디오를 제한 안에서 실행 → OOM 없음, cgroup 최대 2500MB, 프로세스 RSS 3196MB. GPU 쪽은 제한에 다 잡히지 않는다.
  - 버린 대안: 자물쇠 없이 `free -h`만 보고 실행(기존 방식). 확인과 실행 사이에 다른 사람이 모델을 올리면 막을 수 없다.
- **결정**: 평가 결과를 보고 학습 설정(epoch, lr)을 바꾸지 않는다. `docs/mac-training.md`의 "과적합이면 epoch·lr 낮추기" 안내를 지웠다.
  - 이유: 평가 세트로 설정을 고르면 평가 점수가 실제보다 좋게 나온다(평가 세트에 맞춘 것). 원문 확인 포인트와 다르지만 팀 규칙을 따른다.
  - 버린 대안: 원문대로 평가 점수를 보고 다시 학습. 보고하는 점수를 믿을 수 없게 된다.
