# /day-end

오늘 작업을 마무리한다. **커밋은 내가 diff를 보고 승인한 뒤에만 한다. push는 하지 않는다.**

## 1. 오늘 한 일 모으기

- 오늘 날짜: `date '+%Y-%m-%d %a'`
- `git log --since=midnight --stat --format='%h %s'`, `git status --short`, `git diff --stat`
- 오늘 끝낸 실습 단계. `docs/reports/step-NN.md`와 `docs/study/step-NN-*.md`가 있는지 확인한다.
  없으면 `/step-end N`을 먼저 하자고 알린다.
- 이 대화에서 새로 알게 된 사실(모델·보드 특성, 강사 답변, 마감일, 팀 분담)과 실제로 겪은 문제(실패한 테스트, 오류 메시지, 잘못 짚은 가정).

## 2. `docs/roadmap.md` 고치기

파일이 없으면 만들지 말고 "roadmap.md가 없다, 새로 만들까?"를 추천안과 함께 묻는다.

1. **현재 위치**: 끝난 실습 단계의 체크박스를 갱신한다.
2. **날짜별 계획**: 남은 단계를 하루 5시간, 주말 휴식, 팀 분담에 맞춰 다시 맞춘다.
3. **새로 알게 된 사실**: 해당 섹션에 반영한다.
4. **일정이 밀렸으면**: 무엇을 줄일지 추천안을 같이 쓴다.
   형식: 추천안 + 이유 1줄 + 버리는 것 1줄.
   줄일 후보: 5단계 음성 생략, 7단계와 8~10단계 중 한 갈래 선택.
5. **변경 기록**: 파일 맨 아래 "변경 기록"에 `- YYYY-MM-DD: 한 줄 요약`을 추가한다.

## 3. 학습 문서 (`docs/study/`)

### 개념 정리 형식 (두 문서 공통)

개념마다 네 줄:

```markdown
### <개념 이름>
- 정의: <한 줄>
- 비유: <일상 비유 한 줄. 백엔드 개념(DB, 트랜잭션, 큐, 인덱스)에 대응되면 함께 쓴다>
- 이 레포에서는: `<파일>:<라인>` — <거기서 무엇을 하는지>
- 잘못하면: <틀리게 쓰면 실제로 생기는 일>
```

`파일:라인`은 지금 커밋 기준으로 실제 파일을 열어 확인한 위치만 쓴다.

### 3-1. 하루 문서: `docs/study/daily/YYYY-MM-DD.md` (매일)

이미 있으면 덧붙인다. 구성:

1. **오늘 한 일** — 5줄 요약
2. **오늘 처음 나온 개념** — 위 형식. 이전 하루 문서·과제 문서에 이미 나온 개념은 빼고 링크만 건다
3. **실제로 겪은 문제 → 원인 → 해결** — 오늘 대화와 git 기록에 실제로 있었던 것만. **지어내지 않는다.** 없으면 "없음"
4. **직접 쳐 볼 명령 3개와 예상 결과** — sudo 없이 내 계정으로 안전하게 칠 수 있는 명령. 명령 → 예상 결과 → 다르면 의심할 것
5. **아직 모르는 것** — 답을 못 찾은 질문, "추정"으로 남긴 내용

### 3-2. 단계 노트

오늘 끝난 단계의 `docs/study/step-NN-*.md`가 없으면 `/step-end N` 형식으로 쓴다.

### 3-3. 실습 정리: `docs/study/summary.md` (실습 전체가 끝났을 때만)

한 장 요약 / 흐름도(Mermaid) 1~2장 / 단계별 핵심 개념 모음 / 결정과 이유(`docs/decisions.md`) / 단계별 판정표 / 내 처음 가설 vs 실제 결과 / 강사 질의응답 예상 질문 5개 / 팀 프로젝트로 넘길 것.

### 공개 저장소 규칙 (두 문서 모두)

이 저장소는 Public이다. 쓰기 전과 커밋 전에 확인한다.

- 비밀값(RTSP 주소·카메라 계정, HF 토큰)과 카메라 IP를 쓰지 않는다.
- 사진·영상·음성 파일을 넣지 않는다.
- 사람 이름(팀원, 강사)을 쓰지 않는다. "팀원", "강사"로 쓴다.
- 점검: `grep -rnE 'rtsp://|hf_[A-Za-z0-9]{10,}' docs/` 결과가 비어 있어야 한다.

## 4. 커밋 전 점검과 승인

1. 커밋할 파일 목록과 `git diff`(roadmap.md는 전체 diff, 나머지는 `--stat` + 핵심 부분)를 보여 준다.
2. 점검: `.env`, `media/`·사진·영상·음성, 비밀값, 모델 파일(`models/`, `runs/`)이 없는지, `docs/`에 사람 이름·RTSP 주소가 없는지 확인하고 결과를 한 줄로 쓴다.
3. 커밋 메시지 안을 보여 주고 **승인을 기다린다.** 승인 전에는 `git add`/`git commit`을 하지 않는다.
4. 승인하면 커밋하고 `git log -1 --stat`을 보여 준다. push는 하지 않고, 필요하면 명령만 보여 준다.
